## 1. Objetivos y prerrequisitos

Al terminar esta lección deberías poder convertir una hoja de cálculo desordenada en un dataset ordenado (tidy). En concreto: identificar filas, columnas y celdas, aplicar la regla «una fila = una observación, una columna = una variable, una celda = un valor», distinguir formato ancho de formato largo, tratar valores faltantes sin confundirlos con ceros y documentar la limpieza. También deberías poder detectar duplicados, unidades mezcladas y variables escondidas en una celda.

Los prerrequisitos son los tipos de variables, las tablas y las unidades. No necesitas programación; los principios se aplican igual en Excel, en R o en Python. Si entiendes que una tabla es una cuadrícula de valores y que cada columna debe medir una sola cosa, ya tienes la idea.

Autochequeo de entrada, treinta segundos. Una columna se llama «ciudad_temperatura» y contiene «Madrid_28». ¿Qué problema tiene? Si respondiste que mezcla dos variables en una celda, estás listo. Si respondiste que el formato es raro, has visto el síntoma pero no la causa: la celda contiene dos valores y una de ellas es texto.

Un aviso de alcance. Tidy data es una convención, no una ley. Hay formatos anchos útiles para presentar y formatos largos útiles para analizar. La lección no dice que todo deba ser largo siempre; dice que el formato de análisis debe tener una estructura predecible y que la conversión debe ser explícita.

## 2. Por qué importa

La mayor parte del tiempo de un analista se va en limpiar y reestructurar datos. Una hoja ordenada permite agrupar, filtrar, unir y calcular sin transformaciones ad hoc. Una hoja desordenada obliga a escribir código específico para cada tabla, multiplica los errores y hace imposible comparar datasets. La inversión en estructura se recupera en cada análisis posterior.

También importa porque los errores de estructura son silenciosos. Una columna con dos variables mezcladas no da error al abrir el archivo; da error conceptual al analizar. Un valor faltante codificado como 0 se cuela en la media. Un duplicado infla el conteo. La estructura es el primer control de calidad, y el más barato de corregir. Cambiar una celda mal codificada a tiempo evita rehacer todo el análisis después.

En machine learning, la mayoría de las librerías esperan una tabla con una fila por ejemplo y una columna por característica. Si el dataset no está ordenado, el modelo aprende de columnas que no son variables o de valores que no son observaciones. La limpieza no es un paso previo opcional; es parte del modelado. Un error de estructura se propaga al entrenamiento y es más difícil de detectar que un error de código.

Y hay una razón de colaboración: un dataset ordenado se entiende sin conocer al autor. Un dataset desordenado requiere una explicación oral que se pierde. La convención tidy es una forma de documentación implícita. Si otra persona abre la tabla, sabe qué es una fila y qué es una columna sin preguntar. Esa claridad reduce el coste de incorporar a alguien nuevo y de revisar el trabajo meses después.

## 3. Intuición

### La cuadrícula

Una tabla ordenada es una cuadrícula con tres reglas: cada fila es una observación, cada columna es una variable, cada celda es un valor. Si una fila es un día, todas las columnas describen ese día. Si una columna es temperatura, todas las celdas son temperaturas en la misma unidad. La imagen clave es la de una hoja de cálculo con encabezados claros y sin celdas combinadas.

### Ancho y largo

El formato ancho tiene una columna por cada valor de una variable: por ejemplo, una columna «enero», otra «febrero». El formato largo tiene una columna «mes» y otra «valor». El largo es más fácil de agrupar y graficar; el ancho es más fácil de leer en una presentación. Convertir de uno a otro es una operación estándar (pivotar).

### Una celda, un valor

Una celda no debe contener dos datos. «Madrid_28» mezcla ciudad y temperatura; «3 kg» mezcla valor y unidad; «sí, aunque a veces» mezcla respuesta y matiz. La celda debe contener un valor atómico, y la unidad debe estar en el encabezado o en una columna aparte.

### La trampa de Excel

Excel invita a combinar celdas, poner títulos en varias filas y añadir notas al margen. Esas libertades son útiles para presentar y fatales para analizar. Una hoja con celdas combinadas no se puede leer como tabla; una con dos filas de encabezado confunde los tipos. La regla es simple: la hoja de análisis no es la hoja de presentación. Sepáralas.

### La hoja de presentación

Una tabla para presentar puede tener colores, celdas combinadas y totales destacados. Una tabla para analizar debe tener encabezados simples, una fila por observación y celdas atómicas. Son dos artefactos distintos. Intentar que uno haga las dos cosas produce hojas que no se leen bien ni se analizan bien. Genera la presentación a partir del dataset limpio, no al revés.

## 4. Definición y notación

### Tidy data

Un dataset es **ordenado** si cumple tres condiciones:

1. Cada fila es una observación.
2. Cada columna es una variable.
3. Cada celda contiene un único valor.

$$\text{filas}=\text{observaciones},\qquad \text{columnas}=\text{variables}$$

### Formato largo y ancho

El **formato largo** tiene una fila por observación y columnas para las variables, incluidas las de identificación. El **formato ancho** reparte los valores de una variable en varias columnas. Ambos pueden ser válidos; el largo es el que suele necesitar el análisis.

### Valores faltantes

Un valor faltante debe codificarse como ausente (NA, nulo, vacío), no como 0 ni como −1, porque esos son valores posibles. La diferencia entre «no hay dato» y «el dato es cero» es crucial: un ingreso 0 es distinto de un ingreso desconocido. El código de ausencia debe ser único y documentado.

### Duplicados y unidades

Un duplicado es una observación repetida, a veces con distinto identificador. Hay que decidir si se elimina, se agrega o se conserva. Las unidades deben ser homogéneas por columna; si una columna mezcla kg y g, la media no significa nada.

### Esquema y diccionario

Un dataset ordenado se acompaña de un diccionario: nombre de columna, tipo, unidad, valores permitidos y descripción. Ese diccionario es el contrato del dato. Sin él, el analista tiene que adivinar qué significa «nivel 2» o «importe». El diccionario también sirve para validar: si una columna sale de su rango, hay un error.

### Claves y granularidad

La granularidad es el nivel de detalle de una fila: una venta, un día, un cliente. La clave es la combinación de columnas que identifica de forma única una observación. Antes de limpiar, define ambas. Si no sabes qué es una fila, no puedes decidir si hay duplicados ni cómo agregar. La granularidad mal definida produce conteos inflados o medias mezcladas.

## 5. Derivación paso a paso

### Convertir a tidy

**Paso 1. Identifica la observación.** ¿Qué representa una fila? **Paso 2. Identifica las variables.** ¿Qué columnas describen esa observación? **Paso 3. Separa celdas compuestas.** Divide «Madrid_28» en ciudad y temperatura. **Paso 4. Unifica unidades.** Convierte todo a la misma unidad y anótala. **Paso 5. Codifica faltantes.** Usa NA, no 0. **Paso 6. Elimina o justifica duplicados.** **Paso 7. Valida.** Comprueba tipos, rangos y totales.

### Validar un dataset

**Paso 8. Tipos.** Cada columna debe tener un tipo coherente: numérico, texto, fecha. **Paso 9. Rangos.** Una edad negativa o una altura de 500 cm son sospechosas. **Paso 10. Faltantes.** Cuenta y reporta. **Paso 11. Duplicados.** Cuenta y decide. **Paso 12. Totales.** Comprueba que las sumas cuadran con la fuente. **Paso 13. Documenta.** Deja constancia de cada transformación.

### Ancho a largo

**Paso 14. Identifica las columnas que son valores.** «enero», «febrero». **Paso 15. Pivota.** Convierte esas columnas en una variable «mes» y una variable «valor». **Paso 16. Comprueba.** El número de filas debe ser el número de observaciones por mes. **Paso 17. Grafica.** El formato largo permite agrupar por mes sin código especial.

### Un flujo de limpieza

**Paso 18. Copia el original.** Nunca limpies sobre el único archivo. **Paso 19. Inspecciona.** Mira tipos, rangos, faltantes y duplicados. **Paso 20. Normaliza.** Nombres de columnas, unidades, fechas y códigos. **Paso 21. Corrige.** Separa celdas, unifica unidades, codifica faltantes. **Paso 22. Valida.** Comprueba totales y reglas. **Paso 23. Documenta.** Guarda el script o la lista de pasos. **Paso 24. Versiona.** Conserva el original y la versión limpia.

### Validaciones típicas

Una validación es una regla que el dato debe cumplir: edad entre 0 y 120, fecha no futura, importe no negativo, categoría dentro de la lista. Las validaciones detectan errores antes del análisis y se pueden automatizar. Si una fila las incumple, se corrige, se excluye o se marca, pero no se ignora. La validación es el control de calidad que separa un dataset limpio de una hoja con buena voluntad.

### Documentar la limpieza

Cada transformación debe quedar registrada: qué se filtró, qué se imputó, qué se eliminó y por qué. La documentación puede ser un script, un cuaderno o una lista de pasos, pero debe permitir reproducir el dataset final desde el original. Sin esa trazabilidad, el análisis no es reproducible y las decisiones de limpieza se vuelven invisibles y difíciles de discutir con quien lea el análisis después y quiera reproducirlo desde el archivo original sin adivinar nada ni preguntar al autor qué hizo con los datos antes de publicarlos o de compartirlos con el resto del equipo de análisis y de revisión posterior por otra persona del mismo equipo o de otro turno de trabajo del equipo de análisis completo y del revisor que llegue después a revisar el trabajo con calma y sin prisa.

## 6. Ejemplos resueltos

### Celdas compuestas

**Ejemplo 1. Ciudad y temperatura.** Mal: `ciudad_temperatura = "Madrid_28"`. Bien: dos columnas, `ciudad = "Madrid"` y `temperatura = 28`. **Ejemplo 2. Valor y unidad.** Mal: `peso = "3 kg"`. Bien: `peso_kg = 3`. La unidad va en el encabezado.

### Ancho y largo

**Ejemplo 3. Ventas por mes.** Ancho: columnas enero, febrero, marzo. Largo: columnas mes y ventas. La tabla larga:

| Tienda | Mes | Ventas |
|---|---|---:|
| A | enero | 100 |
| A | febrero | 120 |
| B | enero | 80 |

La tabla ancha tendría una fila por tienda y tres columnas de meses. Ambas son correctas; la larga es más fácil de agrupar.

### Un caso con datos

**Ejemplo 4. Encuesta.** Una fila por encuestado, columnas: id, edad, sexo, ingresos, satisfacción. Si «sexo» está codificado 1/2, se documenta. Si «ingresos» tiene «NA», se mantiene como ausente. Si hay un encuestado duplicado, se elimina o se justifica.

### La trampa

**Ejemplo 5. NA como cero.** Codificar ingresos desconocidos como 0 baja la media y distorsiona la distribución. Detección: muchos ceros sospechosos. Corrección: usa NA y reporta la proporción de faltantes. **Ejemplo 6. Celdas combinadas.** Una hoja con celdas combinadas no se puede leer como tabla. Detección: los encabezados no están en una fila. Corrección: descombina y rellena los valores.

**Ejemplo 7. El identificador repetido.** Dos filas con el mismo id pero distinta fecha pueden ser dos observaciones válidas (una por fecha) o un duplicado. La decisión depende de qué sea una observación. Detección: el id no es único. Corrección: define la clave (id+fecha) y documenta.

**Ejemplo 8. El margen en una celda.** Una hoja de ventas incluye una fila de totales al final. Si se lee como datos, el total se convierte en una observación gigante y distorsiona la media. Detección: una fila con valores mucho mayores y sin id. Corrección: separa totales de datos y valida que la suma coincida.

**Ejemplo 9. El formato ancho de una encuesta.** Una encuesta guarda una columna por pregunta: q1, q2, q3. Si quieres analizar la respuesta media por pregunta, necesitas formato largo con columnas «pregunta» y «respuesta». El formato ancho es cómodo para introducir datos; el largo, para analizarlos.

**Ejemplo 10. La fecha como texto.** Una columna de fechas guardada como texto no se puede ordenar ni restar. Detección: el orden alfabético no coincide con el cronológico. Corrección: conviértela a tipo fecha y comprueba el formato (día/mes vs mes/día). En EE. UU. y en Europa, 03/04 puede significar dos fechas distintas.

## 7. Errores y malinterpretaciones

### Los errores que más cuestan

**Error 1. Mezclar variables en una celda.** Detección: texto con separadores. Corrección: separa en columnas. **Error 2. Codificar faltantes como 0.** Detección: ceros imposibles. Corrección: usa NA.

**Error 3. Mezclar unidades en una columna.** Detección: kg y g juntos. Corrección: convierte y anota. **Error 4. Duplicados sin tratar.** Detección: el conteo supera la población. Corrección: identifica y decide.

**Error 5. Encabezados en varias filas.** Detección: la tabla no se puede leer con un solo encabezado. Corrección: normaliza a una fila de nombres. **Error 6. Perder la trazabilidad.** Detección: no se sabe qué se filtró. Corrección: documenta cada paso.

**Error 7. Confundir una fila de totales con un dato.** Detección: aparece una fila con valores mucho mayores y sin identificador. Corrección: separa los totales y valida que la suma de las filas coincida.

**Error 8. No fijar la granularidad.** Detección: no se sabe si una fila es una venta, un día o un cliente. Corrección: define la observación y la clave antes de limpiar.

## 8. Conexiones y transferencia

Tidy data conecta con los tipos de variables, las tablas y la limpieza. También con la reproducibilidad: un dataset ordenado y documentado se puede analizar con código estándar y comparar con otro. Sin esa estructura, cada análisis es artesanal y difícil de auditar.

La estructura también conecta con la inferencia: si una fila no es una observación independiente, el tamaño de muestra efectivo no es el número de filas. Datos agrupados o duplicados inflan n y estrechan los intervalos sin añadir información. La limpieza no es solo estética; afecta a la validez de las conclusiones.

En machine learning, el formato tidy es el que esperan las librerías: una fila por ejemplo, una columna por característica. En bases de datos, el modelo relacional separa entidades y relaciones; el tidy es su versión plana. En periodismo de datos, la hoja limpia es la base de cualquier gráfico reproducible.

Una transferencia directa: si una hoja tiene una columna por cada año y quieres calcular la tendencia, conviértela a formato largo con columnas «año» y «valor». La tendencia se calcula igual, pero el código es más simple y menos propenso a errores. Y si añades un año nuevo, no hay que cambiar el código, solo añadir filas.

## 9. Práctica y resumen

1. ¿Qué es una fila en tidy data? — **Solución:** Una observación.
2. ¿Qué es una columna? — **Solución:** Una variable.
3. ¿Qué es una celda? — **Solución:** Un único valor.
4. ¿Cómo se codifica un faltante? — **Solución:** NA, no 0.
5. ¿Qué formato es más fácil de agrupar? — **Solución:** El largo.
6. «Madrid_28» viola... — **Solución:** Una celda, un valor.
7. ¿Qué hacer con duplicados? — **Solución:** Identificarlos y decidir si se eliminan, agregan o conservan, documentándolo.
8. ¿Por qué documentar la limpieza? — **Solución:** Para reproducir y auditar el análisis.

**Mapa de cinco ideas.** Primera: una fila, una observación. Segunda: una columna, una variable. Tercera: una celda, un valor. Cuarta: NA no es cero. Quinta: el formato largo facilita el análisis y la conversión debe documentarse.
